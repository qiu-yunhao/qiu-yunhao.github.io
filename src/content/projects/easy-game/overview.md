# easy_game 项目概览

## 项目定位

`easy_game` 是一个面向修仙题材互动叙事的 Python 项目。它不是传统意义上只处理数值和回合规则的游戏 Demo，而是把剧情规划、导演调度、角色行动、玩家输入、旁白生成、历史记忆和存档能力拆成一组可以替换的模块，再通过 `Graph` 层串成持续推进的叙事流程。

项目支持两条运行路径：

- `heuristic`：只使用本地启发式逻辑，适合离线调试、状态流转验证和回归测试。
- `agent-first` / `live`：优先使用 LLM Agent 生成剧情、角色行为和旁白，在部分 Agent 不可用时回退到启发式逻辑。

## 核心能力

- 生成故事前提、章节大纲、角色阵容和场景候选。
- 调度当前舞台状态，决定谁在场、谁响应、下一位行动者是谁。
- 解析玩家自然语言输入，并支持背包、状态、关系、任务、存档和读档等工具请求。
- 将结构化行动写入历史、角色关系、情绪和长短期记忆。
- 生成旁白文本，并支持叙事风格预设和文本润色。
- 在 Web 模式下提供浏览器端 UI、HTTP API 和可选数据库存档。

## 模块拆分

项目把不同职责拆成清晰的目录：

- `Actor`：处理角色行动、关系变化和记忆更新。
- `Director`：负责舞台调度、焦点角色、响应队列和导演提示。
- `Graph`：组合故事创作、章节准备、beat 执行和转场流程。
- `History`：维护历史记录、摘要压缩和多层记忆。
- `Narrator`：把行动队列转成旁白文本，并提供兜底叙事。
- `Persistence`：维护 SQLAlchemy 存档模型、快照保存和读取。
- `PlayerControl`：处理玩家输入、语义解析和玩家工具调用。
- `PlayerWriter`：生成故事前提、章节大纲和场景候选。
- `SceneEnd`：判断场景或章节是否结束。
- `Scheduler`：选择下一位行动者。
- `StylisticPolish`：润色非语言动作和旁白片段。
- `frontend`：提供浏览器端交互界面。

## 展示重点

这个项目最适合放在作品集里的地方，是它把“互动叙事”拆成了多个可测试的工程单元。LLM 不是直接接管整个游戏，而是被约束在故事规划、角色行动、旁白、语义解析等明确节点中；当模型不可用时，本地启发式逻辑仍然可以维持流程继续运行。

这种设计让项目既能展示 Agent 应用的实验性，也能保留工程项目需要的确定性、可测试性和可替换性。
